## Working assumptions and open decisions

- Synthetic accounts only through the initial demonstration. The first target is instruction format and M12 integrates a single planning workflow. Additional targets and modules require their own evidence and acceptance criteria.
- M1 selects exact package versions and local setup commands. M3 chooses an LLM checkpoint and provider. M5 chooses an embedding checkpoint, vector size and retrieval cutoff. Define retention windows and provider data-handling requirements before any approved personal data enters the system.
- M6–M8 validate dataset volume, scenario mix, gate thresholds and drift logic. A sparse account can remain on explicit settings and defaults while evidence accumulates.
- Main research risks are unrealistic synthetic preference dynamics, feedback influenced by model suggestions, leakage between related scenarios, sparse updates, and incorrect retrieval or deletion. Track these with held-out families, exposure flags, point-in-time tests, abstention, review and deletion rehearsals. LLM output variance and external latency should be measured with repeat runs.

## Milestone review workflow

After each milestone, run the relevant checks, inspect Git status and diff, and document actual results, changed files, manual tests, assumptions and limitations. Include explicit staging paths and a Conventional Commit message. The user controls commit and push.

For M0 manual review, start at the README. Open every design link and render the three architecture diagrams and database ER diagram in a Mermaid-capable viewer. Trace a synthetic checklist choice from consented intake to a possible model update and confirm that a saved preference still takes precedence. Check that all fourteen milestones specify dependencies, scope, deliverables, acceptance and tests.
